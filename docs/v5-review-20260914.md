## 复核结论

未发现需要继续阻断提交的新增缺陷。复核中确认并修正两处今天新增的边界问题：

1. 编辑语义词汇时，如果选中了旧词又填写了新词，原实现会先覆盖选中项，再追加新词，导致原词丢失。现在保存会保留原词并独立新增新词；profile 测试覆盖该行为。
2. profile 原子保存的临时文件初始 `ofstream` 权限为 `0644`，存在短暂的过宽权限窗口。现在先完成内存序列化，再以 `0600` 创建临时文件并写入，保留原子替换。

耗时字段也已补齐：可解析 WAV 的 `audio_duration_ms`、任务排队时间 `queue_latency_ms`、ASR/SLM 阶段汇总、`slm_called`，以及 GGUF worker 提供时白名单透传 `mel_ms`、`encode_ms`、`decode_ms`。总处理时间从 worker 启动计起，排队时间单独记录。Fcitx5 在调用 `commitString` 前捕获 UTC 时间 `committed_at` 和单调时钟，并记录 `release_to_commit_latency_ms`；该边界已完成源码审核，Fcitx 相关回归测试通过，尚无真实输入框现场验证。

使用本机保存的两段错误录音分别回放 Q4 与 Q8，并保持当前术语上下文。两种量化模型在两段样本上都没有恢复用户原意：第一段中 Q4 和 Q8 产生了不同的错误结果，第二段短确认句中两者产生了相同的错误结果。原始诊断事件显示错误已经出现在 ASR，DeepSeek 保留了 ASR 文本；没有据此修改提示词，也不据此推导整体准确率或模型 benchmark。
